# Where I Parked v1.0.0

The first release of Where I Parked delivers the completed mobile-first MVP: save where you parked and find that location when you reopen the app in the same browser and origin. No account or database is required.

[Open the live application](https://whereiparked-eta.vercel.app/)

## Features

- Display your current location on a Leaflet/OpenStreetMap map, with estimated location accuracy when available.
- Tap **Parked** to acquire a fresh location and save one parking spot.
- Distinguish the parked car from your current location with separate markers.
- Persist the parking spot in `localStorage` and restore it on reopening, even when current location access is unavailable.
- Replace the saved spot with a new one, without keeping a history.
- Remove the saved spot after confirmation, without requiring a new location reading. Storage failures preserve the saved parking state.
- Provide optional reverse geocoding through `GET /api/location/reverse`, with coordinate validation, structured errors, per-instance caching, and external-request throttling.

**Reverse geocoding is intentionally disabled in the public deployment.** Without `GEOCODING_USER_AGENT`, a valid address lookup returns `503 GEOCODING_UNAVAILABLE`. Saving, restoring, and removing a parking spot remain available.

## Technologies

- Java 21, Spring Boot 4.1.2, and the Maven Wrapper.
- HTML5, CSS3, and vanilla JavaScript, served as static resources by Spring Boot.
- Leaflet, OpenStreetMap, the browser Geolocation API, and `localStorage`.
- Spring REST Client and an optional Nominatim-compatible reverse-geocoding integration.

## Tests and infrastructure

- Java tests use JUnit, Mockito, and MockMvc, with Mockito configured as an explicit agent in Maven Surefire.
- JavaScript tests use the native `node:test` runner with no npm dependencies; CI uses Node.js 24.
- GitHub Actions defines independent Java, JavaScript, and Docker jobs for pull requests and pushes to `main`, with manual execution also available.
- The Docker job builds the image, checks the served HTML and JavaScript over loopback HTTP, verifies HTTP 400 for invalid API input, and checks that the runtime user is non-root. Reverse geocoding stays disabled during these checks.
- A multi-stage Docker build packages the application with a Java 21 JDK and runs it with a Java 21 JRE as a non-root user.
- Frontend and backend are hosted together in a Docker container on Vercel Hobby. The application reads `PORT` and defaults to `8080`.
- English and Brazilian Portuguese READMEs document usage and operation. Historical development specifications are preserved in `docs/step/`.

## Known limitations

- Only one parking spot is stored per browser and origin. There are no accounts, parking history, server-side parking storage, or cross-device synchronization.
- Clearing site data or losing access to `localStorage` can remove or prevent persistence of the saved spot.
- Capturing a new spot requires location permission and a compatible browser. Geolocation requires HTTPS outside localhost, and reported accuracy is an estimate.
- The map depends on external Leaflet/OpenStreetMap resources and network availability.
- Address lookup is optional and disabled in the public deployment. Its cache and request throttling are local to each application instance.
- The Vercel Container runtime may experience cold starts after inactivity.
